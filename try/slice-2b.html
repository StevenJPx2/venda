Slice 2b · The admin

A working admin, built from lazy plugins and served on the same origin as the API. Browse content and file problems, invite someone, manage people, change your password and create API tokens. Content is read-only until slice 3 adds saving and publishing.

Open the real admin

Sign in with owner@venda.local / try-venda-owner, throwaway credentials for this machine. You stay signed in across restarts of pnpm try; pnpm try --fresh starts clean.

Open the admin ↗
  1. Open Journal, then an entry. Check the writing preview and the draft state.
  2. Open one collection of each kind. Journal and Pages are lists, Authors is a table that opens a record as a form, and Home opens straight into its one entry. Releases is a posts collection whose config.ts names the table view.
  3. Open Content problems. The missing-title file is recorded here.
  4. Invite an author, copy the join link, and open it in a private window. Join, then browse content: the author cannot see drafts or administrator settings.
  5. Create an API token. Copy its secret, then revoke it through the confirmation.
  6. In People, disable the invited person. Their next request returns them to sign-in.
  7. Resize to 390px. Open navigation, choose a page, and check that it closes.

The automated browser suite exercises these actions: pnpm e2e admin. The checks below verify the serving and API boundaries; they do not pretend to test the UI.
